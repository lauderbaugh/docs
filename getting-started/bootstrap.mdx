\## Bootstrapping Your Documentation After you confirm your documentation skeleton, Syscribe runs a \*\*bootstrap\*\* to generate an initial set of documentation drafts for your repository. This happens automatically and does not require any action from you beyond confirming the skeleton. ### What Bootstrapping Does Bootstrapping processes your existing codebase — or recent commit history — and generates a first draft for every section in your confirmed skeleton. By the time bootstrapping completes, you have a full set of drafts ready to review, edit, and deploy. ### Bootstrap vs. Backfill Syscribe uses two modes depending on your repository's history: - \*\*Bootstrap\*\* — runs when there is no prior documentation history. Syscribe evaluates your codebase as it stands today and generates drafts for all confirmed sections. - \*\*Backfill\*\* — runs when your repository has existing commit history that Syscribe has not yet processed. Syscribe works through past commits in order, building up documentation history before generating the current drafts. Syscribe selects the mode automatically. You do not need to choose. ### Watching Bootstrap Progress While bootstrapping runs, the progress view shows each documentation section as a node. You can see the status of every node at a glance: - \*\*Pending\*\* — the section is queued and waiting to be processed. - \*\*In progress\*\* — the agent is currently generating a draft for this section. - \*\*Complete\*\* — the draft has been generated successfully. - \*\*Failed\*\* — the agent encountered an error for this section. A progress bar at the top shows how many sections are complete out of the total. Once all sections reach a terminal state, bootstrapping is done. ### After Bootstrap Completes When bootstrapping finishes, you are taken to the activity feed where you can find the bootstrap event and begin reviewing the generated drafts. The drafts work exactly like any other generated draft — you can approve, edit, reject, and deploy them using the same workflow. ### If Bootstrap Fails If bootstrapping encounters a persistent error, the status in your repository settings panel shows the failure. You can retry the bootstrap from the settings panel. If individual sections fail, those sections show a \*\*Failed\*\* status in the progress view — you can regenerate them individually once bootstrap completes.
