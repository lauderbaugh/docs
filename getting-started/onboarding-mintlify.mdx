\## Onboarding a Mintlify Repository When you onboard a repository with Mintlify as its deployment target, the system reads your existing \`docs.json\` to understand your current navigation structure. You can use this to import your existing pages rather than starting from a blank skeleton. ### Connecting Your Docs Repository Before onboarding, make sure you have: - A GitHub repository containing your Mintlify site with a \`docs.json\` navigation file. - A personal access token or GitHub App installation with read and write access to that repository. - The repository path (\`owner/repo\`), branch, and base path ready to enter in your deployment target settings. ### Importing an Existing Structure During onboarding, select \*\*Rediscover\*\* to import the page structure from your existing \`docs.json\`. The system reads your navigation tabs and groups and proposes them as your documentation skeleton. You can deselect pages you do not want to track before confirming. If you prefer to start fresh, select \*\*New Skeleton\*\* instead. The system proposes a default structure based on your doc types, and you can customise it before confirming. ### After Onboarding Once onboarding is complete, every approved draft you deploy creates or updates an MDX file in your docs repository and keeps \`docs.json\` in sync automatically. You do not need to edit \`docs.json\` by hand.
