\## Agent Directions Agent directions let you give the documentation agent specific instructions it must follow when generating content. You can set directions at the organisation level, the repository level, or per doc type, and you can scope them to particular sections of your documentation hierarchy. ### How Directions Work When the agent generates a draft, it resolves an effective instruction by merging directions from all applicable scopes in order of specificity. A more specific direction — for example, one scoped to a particular section — takes precedence over a broader one set at the repository or organisation level. You can preview the resolved effective instruction for any combination of doc type and section before saving. Use the \*\*Preview\*\* panel to confirm that the agent will receive the instruction you expect. ### Setting Directions To configure agent directions: 1. Navigate to \*\*Settings → Agent Directions\*\* for your repository. 2. Select the doc type you want to configure: \*\*User-Facing\*\*, \*\*Internal\*\*, or \*\*API\*\*. 3. Enter your instructions in the text field. You can write in plain text or Markdown. 4. Optionally scope the direction to a specific section by selecting a parent section from the hierarchy. 5. Save your changes. Directions have a maximum length of 4,000 characters per entry. ### Scoping Directions to Sections You can attach a direction to a specific node in your documentation hierarchy. When you do, the agent applies that direction only when generating drafts for that section and its children. This lets you give targeted guidance — for example, instructing the agent to use a particular tone or include specific detail — without affecting unrelated sections. ### Previewing the Effective Instruction Before saving, you can preview the instruction the agent will actually use for a given doc type and section. The preview combines all applicable directions and shows you the merged result. If the effective instruction looks wrong, adjust your direction entries and preview again before saving.
