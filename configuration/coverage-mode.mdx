\## Coverage Mode Coverage mode controls how aggressively the documentation agent proposes new sections when it processes a code change. You configure coverage mode per doc type in your repository settings. ### Available Modes - \*\*Conservative\*\* — the agent only updates existing sections and rarely proposes new ones. Use this mode when your documentation structure is mature and you want to minimise noise. - \*\*Balanced\*\* — the agent updates existing sections and proposes new sections when a code change clearly warrants them. This is the default mode for most repositories. - \*\*Aggressive\*\* — the agent proactively proposes new sections for any change it considers underdocumented. Use this mode when you are building out a new documentation area and want broad coverage. ### Custom Coverage Instructions In addition to selecting a coverage mode, you can provide custom instructions that further guide the agent's gap-analysis behaviour. For example, you might instruct the agent to always propose a section for new public API endpoints or to skip internal utilities. Custom instructions are applied on top of the selected mode. Enter your custom instructions in the \*\*Coverage mode instructions\*\* field in your doc type settings. The agent appends these instructions to its gap-analysis prompt for every code change it processes. ### How Coverage Mode Affects Gap Analysis When the agent evaluates a code change, it runs a gap analysis to identify sections that may need new documentation. The coverage mode instructions are injected into this analysis, telling the agent how many proposals to generate and how broadly to interpret the change. A more aggressive mode produces more proposals; a conservative mode produces fewer.
