\## Doc Types Doc types let you organise your documentation into distinct categories, each with its own deployment target, agent directions, and approval routing. Every piece of documentation the system generates belongs to exactly one doc type. ### Available Doc Types - \*\*User-Facing\*\* — documentation intended for your end users, such as product guides and how-to articles. - \*\*Internal\*\* — documentation for your own team, such as architecture notes and runbooks. - \*\*API\*\* — reference documentation for your public or private APIs. ### Enabling a Doc Type You can enable or disable each doc type in your repository settings. When a doc type is enabled, the documentation agent generates drafts for that category whenever it processes a code change. When it is disabled, the agent skips that category entirely. ### Switching Between Doc Types on the Review Page The pull request review page organises drafts by doc type. Use the tabs at the top of the section tree to switch between your enabled doc types. The tab for each doc type shows you at a glance how many drafts are pending or approved within that type, so you can prioritise your review. ### Deployment Target per Doc Type Each doc type has its own deployment target. This means your user-facing docs can go to Mintlify while your API reference goes to SwaggerHub, for example. You configure the target and its fields separately for each doc type. See \[Deployment Targets\](/configuration/deployment-targets) for the full list of supported targets and their configuration fields.
