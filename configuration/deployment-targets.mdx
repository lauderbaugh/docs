## Deployment Targets

A deployment target tells the documentation system where to publish your approved drafts. Each doc type in your configuration can point to a different target, so your internal docs, user-facing docs, and API reference can each live in the right place.

### Supported Targets

-   **Mintlify** — pushes MDX files to a GitHub repository that serves a Mintlify docs site and keeps the `docs.json` navigation updated.
    
-   **GitHub Pages** — publishes content to a GitHub repository configured for GitHub Pages.
    
-   **Confluence** — writes pages to a Confluence space.
    
-   **Readme** — syncs content to a Readme.com project.
    
-   **SwaggerHub** — publishes API definitions to SwaggerHub.
    

### Configuring a Target

You configure deployment targets per doc type in your repository settings. Each target requires a set of fields specific to that platform:

-   **Mintlify** — repository (`owner/repo`), branch, and base path.
    
-   **GitHub Pages** — repository (`owner/repo`) and branch.
    
-   **Confluence** — space key, base URL, and credentials.
    
-   **Readme** — API key and version slug.
    
-   **SwaggerHub** — owner, API name, and API key.
    

After you save a target configuration, the system uses it for all subsequent deployments of that doc type.

### Syncing and Rescanning

Once a target is configured, you can trigger a manual sync to push all approved content to the target immediately. Use **Rescan** to re-index existing content without pushing new changes — this is useful after you make edits directly in the target platform.
