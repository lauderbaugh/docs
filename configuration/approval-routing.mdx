\## Approval Routing Approval routing lets you control which team members are notified or required to review documentation drafts for a given repository, doc type, or deployment target. You configure routing rules in your organisation settings. ### How Routing Rules Work A routing rule maps a combination of repository and deployment target to a specific user. When the agent generates a draft that matches the rule, the specified user receives a review assignment. Rules are evaluated in the order they appear and the first match wins. ### Configuring Routing Rules To add a routing rule: 1. Navigate to \*\*Settings → Team\*\* and open the \*\*Routing\*\* tab. 2. Select the repository the rule applies to. 3. Select the deployment target within that repository. 4. Select the team member who should receive review assignments. 5. Select \*\*Add Rule\*\* to save. To remove a rule, select the delete action next to it in the rules list. ### Repository and Target Availability Only repositories and targets that you have already connected appear in the routing rule form. If you do not see a repository or target, connect it first in your repository settings before creating a routing rule. ### Member Roles Routing rules work alongside your team's role assignments. Make sure the member you route to has at least \*\*Reviewer\*\* access on the relevant repository so they can approve and reject drafts.
