\## Not Applicable Drafts When the documentation agent determines that a code change does not require a documentation update for a particular section, it marks that draft as \*\*Not Applicable\*\* instead of generating content. This saves you from reviewing empty or irrelevant drafts. ### When a Draft Is Marked Not Applicable The agent marks a draft as Not Applicable when its relevance check concludes that the change has no meaningful impact on the section's documentation. Common reasons include: - The change is internal to the codebase (a refactor, a test update, a dependency bump) and does not alter any documented behaviour. - The affected code is not related to the section's subject matter. - The change is too minor to warrant a documentation update. ### Viewing Not Applicable Drafts Not Applicable drafts are hidden from the main section tree by default. You can reveal them by toggling the \*\*Show not applicable\*\* option. Each Not Applicable draft shows the agent's reasoning so you can understand why it concluded no update was needed. ### Overriding a Not Applicable Decision If you disagree with the agent's decision, select \*\*Regenerate\*\* on the Not Applicable draft. The agent will re-evaluate the change and attempt to produce documentation content. You can also edit the section manually and approve it without regenerating.
