\## Approve and Deploy The \*\*Approve and Deploy\*\* action lets you approve a draft and publish it to your documentation destination in a single step, without a separate deployment action. ### When to Use Approve and Deploy Use \*\*Approve and Deploy\*\* when you have reviewed a draft and want to publish it immediately. This is the fastest path from a generated draft to live documentation. If you want to batch-approve drafts first and deploy them later — for example, to publish everything at the end of a sprint — use the separate \*\*Approve\*\* and \*\*Deploy\*\* actions instead. ### Who Can Approve and Deploy You can approve and deploy a draft when it is in the \*\*Draft\*\* or \*\*In Review\*\* status. Drafts that are already \*\*Approved\*\*, \*\*Deployed\*\*, or \*\*Rejected\*\* are not eligible for the combined action. ### Scope Options Like standalone approve and deploy actions, the combined action is available at three levels: - \*\*This section\*\* — approves and deploys the draft currently selected in the section tree. - \*\*All in this doc type\*\* — approves and deploys every approvable draft within the current doc type. - \*\*All\*\* — approves and deploys every approvable draft across all doc types for this pull request. ### Confirmation Dialog Before the system acts, a confirmation dialog lists every section that will be affected, grouped into updates (existing sections) and proposals (new sections). Review the list to make sure the scope is correct, then confirm to proceed. ### Force Redeploy If a draft has already been deployed, you can still select \*\*Deploy\*\* to push the current content again. This is useful after you make edits to a deployed draft and want the changes to go live without creating a new draft cycle.
