title: "Deploying Multiple Drafts at Once"
---

\## Deploying Multiple Drafts at Once Instead of deploying one draft at a time, you can deploy all approved drafts for a doc type or for the entire pull request in a single action. Bulk deployment is faster and ensures your navigation stays consistent because the integration batches the underlying file and navigation writes. ### Scope Options When you trigger a bulk deploy, you choose the scope: - \*\*This section\*\* — deploys only the draft currently open in the editor. - \*\*This doc type\*\* — deploys every approved draft within the currently selected documentation type. - \*\*All\*\* — deploys every approved draft across all documentation types for this pull request. ### Approve and Deploy If your drafts are still in the \*\*Pending\*\* state, use \*\*Approve and Deploy\*\* to approve and publish them in one step. The same scope options apply — you can approve and deploy a single section, all sections in a doc type, or all sections across every doc type. ### How Batching Works When you deploy more than one draft at a time, the integration collects all the file writes and navigation updates and executes them together. For Mintlify, this means \`docs.json\` is updated once for the entire batch rather than once per file, which prevents conflicts when many pages are deployed simultaneously. If a conflict does occur during the navigation update, the integration retries automatically. ### Force Redeploying Already-Deployed Drafts Drafts marked as \*\*Deployed\*\* are excluded from standard bulk deploys. To push already-deployed content again — for example after editing a draft or changing your target configuration — use \*\*Force Deploy All\*\* from your repository settings. This redeploys every section regardless of its current status.
