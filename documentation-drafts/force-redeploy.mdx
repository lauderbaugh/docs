\## Force Redeploying a Draft Once a draft reaches the \*\*Deployed\*\* status, standard deploy actions skip it to prevent accidental overwrites. You can override this behaviour when you need to push the same content again — for example after editing a deployed draft or updating your deployment configuration. ### When to Force Redeploy Use a force redeploy when: - You have edited a deployed draft directly in the editor and want to push the updated content. - You have changed your deployment target configuration and want to re-publish existing content to the new target. - A deployment succeeded but the content did not appear correctly in the target platform. ### How to Force Redeploy a Single Section 1. Select the deployed draft in the section tree. 2. The deploy button changes to indicate a redeploy action is available. 3. Confirm the action. The system pushes the current draft content to your deployment target, overwriting the existing file. The draft status remains \*\*Deployed\*\* after a force redeploy. ### Force Redeploying Multiple Sections To push every section — including already-deployed ones — navigate to your repository settings and select \*\*Force Deploy All\*\*. This triggers a bulk redeploy of all sections for the configured doc type, regardless of their current status. Use this option carefully. It overwrites all existing files in your target repository with the current draft content.
