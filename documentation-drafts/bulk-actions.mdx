\## Bulk Approve, Deploy, and Reject The review interface lets you act on multiple drafts at once so you can move quickly through a large pull request without approving or deploying each section one by one. ### Granularity Levels Bulk actions are available at three levels of granularity: - \*\*Section\*\* — acts on only the draft currently selected in the section tree. - \*\*Doc type\*\* — acts on all eligible drafts within the currently active documentation type (for example, all User-Facing drafts). - \*\*All\*\* — acts on every eligible draft across all documentation types for this pull request. ### Bulk Approve Select \*\*Approve this section\*\*, \*\*Approve all \[doc type\]\*\*, or \*\*Approve all\*\* from the action bar. The system approves every draft that is currently in an approvable state (Draft or In Review). Drafts that are already Approved, Deployed, or Rejected are skipped. ### Bulk Approve and Deploy \*\*Approve and Deploy\*\* combines both steps in a single action. The system approves each eligible draft and immediately queues it for deployment. Use this when you are confident in the generated content and want to publish without a separate deploy step. ### Bulk Deploy If you have already approved drafts and want to publish them in one go, select \*\*Deploy all \[doc type\]\*\* or \*\*Deploy all\*\*. Only drafts in the \*\*Approved\*\* state are deployed. ### Bulk Reject Select \*\*Reject all\*\* to reject every draft in the current pull request that has not yet been deployed. You are prompted to confirm before the action runs. Rejected drafts can be regenerated individually afterwards. ### Confirmation Modal For bulk actions that affect more than one section, a confirmation modal lists every draft that will be affected, grouped by whether it is an update to an existing section or a proposal for a new section. Review the list and confirm to proceed.
