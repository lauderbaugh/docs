\## Proposed Sections When the documentation agent identifies a code change that warrants new documentation but cannot map the content to an existing section, it creates a \*\*proposed\*\* draft. Proposed drafts represent entirely new sections the agent recommends adding to your documentation structure. ### How Proposals Appear Proposed drafts appear in the section tree under their doc type, separated from update drafts. The tree labels them so you can distinguish new proposals from updates to existing sections. ### Accepting a Proposal To accept a proposed section: 1. Select the proposed draft in the section tree. 2. Review the generated content in the editor. 3. Confirm or change the parent section using the parent picker. 4. Select \*\*Approve\*\* to accept the proposal. When you approve a proposal, the system creates a new documentation node at the chosen location. If your integration supports automatic page creation — such as the Notion integration — the system scaffolds the new page in your deployment target at the same time. ### Changing the Parent Section Before approving a proposed draft, you can reassign it to a different parent section. Select the parent picker control and choose the section where the new page should live. The agent's suggested parent is pre-selected, but you can override it at any time before approval. ### Rejecting a Proposal If you do not want to create the proposed section, select \*\*Reject\*\*. Rejected proposals are hidden from the default view. They remain accessible in the pull request history if you want to revisit them later.
