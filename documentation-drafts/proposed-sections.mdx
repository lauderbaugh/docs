\## Proposed New Sections When the documentation agent identifies a code change that warrants an entirely new documentation section — one that does not yet exist in your hierarchy — it creates a \*\*proposed section\*\* draft. Proposed sections let you expand your documentation structure without manually creating nodes first. ### How Proposed Sections Appear Proposed sections appear in the section tree alongside your existing sections, visually distinguished so you can tell them apart. Each proposed section has a suggested parent — the node in your hierarchy where the new section would live if you accept it. ### Accepting a Proposed Section When you approve a proposed section draft, the system creates the section node in your documentation hierarchy and marks the draft as approved. The section is then available for deployment like any other draft. ### Changing the Parent of a Proposed Section If the agent's suggested parent is not the right place for the new section, you can reassign it before approving. Select the proposed section in the tree, then use the parent selector to choose a different location in your hierarchy. The system updates the proposed parent and you can proceed with approval. ### Rejecting a Proposed Section If you do not want the new section at all, you can reject the proposal outright. Rejecting removes the proposed node from the tree and the draft is discarded. The agent will not repropose the same section for the same pull request.
