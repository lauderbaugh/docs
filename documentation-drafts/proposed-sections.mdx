\## Proposed Sections In addition to updating existing documentation sections, the agent can identify gaps in your documentation and propose entirely new sections to fill them. A proposed section is a draft that targets a location in your documentation tree that does not yet exist. ### How the Agent Proposes Sections When the agent processes a pull request, it evaluates your existing documentation structure alongside the code changes. If it detects that a change introduces functionality, concepts, or APIs that are not covered anywhere in your current documentation, it creates a proposed section and suggests where in the hierarchy it should live. Each proposal includes: - \*\*Section path\*\* — the intended location in your documentation tree. - \*\*Section heading\*\* — the suggested H2 heading for the new page. - \*\*Parent\*\* — the existing section the proposal should nest under. - \*\*Nesting level\*\* — whether the section should be a top-level page, sub-page, or section within a page. - \*\*Reasoning\*\* — the agent's explanation of why this section should exist. ### Reviewing a Proposal Proposed sections appear in the section tree alongside regular drafts and are clearly labelled as proposals. Select a proposed section to open it in the editor and read the agent's reasoning and generated content. The editor panel shows the current parent label and nesting level for the proposal so you can confirm the agent has placed it in the right location before you approve. From the editor you can: - \*\*Edit the content\*\* before approving. - \*\*Change the parent node\*\* — if the agent suggested the wrong location in your hierarchy, reassign it to a different parent. The section path updates automatically. - \*\*Approve and deploy\*\* — accept the proposal and publish it to your documentation target. - \*\*Reject the proposal\*\* — dismiss it if you do not want the new section created. Rejected proposals are not deployed. ### Changing the Parent Node To move a proposed section to a different location in your documentation tree: 1. Open the proposed section in the editor. 2. Select a new parent from the parent selector. 3. Save the change. The section path recalculates automatically based on the new parent you select. ### Protected Sections and Proposals The agent will not propose new sections inside a protected section. If you want the agent to resume suggesting content for a part of your hierarchy, remove the protection first.
