\## Proposed New Sections In addition to updating existing documentation sections, the agent can propose entirely new sections that do not yet exist in your documentation structure. You review proposed sections the same way you review updates, but they have additional actions available. ### What Makes a Section a Proposal A proposed section is one the agent believes should be created — for example, when a code change introduces a feature that has no corresponding documentation page. Proposed sections appear in the section tree alongside regular updates, but they are visually distinguished so you can identify them quickly. ### Approving a Proposed Section When you approve a proposed section, the system adds it to your documentation skeleton as a confirmed node. Once confirmed, the section behaves like any other section and can be deployed to your documentation target. ### Rejecting a Proposed Section If you decide a proposed section is not needed, you can reject it. Rejecting removes it from the review queue without adding it to your skeleton. ### Changing the Parent of a Proposed Section Before approving a proposal, you can reassign it to a different parent node in your documentation hierarchy. This lets you place the new section exactly where it fits best in your existing structure rather than accepting the agent's default placement. 1. Select the proposed section in the tree. 2. Choose \*\*Change parent\*\* from the section actions. 3. Select the parent node you want from the picker. 4. Approve the section to confirm the new placement.
