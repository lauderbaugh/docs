\## Managing Documentation Drafts When the documentation agent processes a pull request, it generates drafts organized by documentation type and section. You can review, edit, approve, reject, regenerate, and deploy each draft individually or in bulk. ### Understanding Draft Status Each draft displays a status badge so you can see its current state at a glance: - \*\*Draft\*\* — The draft has been generated and is waiting for your review. - \*\*In Review\*\* — The draft is actively being reviewed. - \*\*Approved\*\* — You have approved the draft and it is ready to deploy. - \*\*Rejected\*\* — You have rejected the draft. You can regenerate it if needed. - \*\*Not Applicable\*\* — The agent determined this section does not require documentation for this change. - \*\*Deployed\*\* — The draft has been published to your documentation. - \*\*Failed\*\* — The deployment encountered an error. ### Navigating the Section Tree The review page displays a section tree on the left side of the screen. Each node in the tree represents a documentation section. Select a node to open that section's draft in the editor on the right. The tree groups sections by documentation type. Within each type, sections nest according to your documentation hierarchy. Top-level sections appear at the root of each group. Nested sections are indented beneath their parent. A dot indicator on each node reflects the current status of that section's draft at a glance. ### Reviewing and Editing a Draft To review a draft: 1. Select a section in the tree. 2. Read the generated content in the editor panel. 3. Make any edits directly in the editor. 4. Choose one of the actions described below. If a draft is marked \*\*Not Applicable\*\*, the agent determined no documentation update is needed for that section. You can still regenerate it if you disagree. ### Approving Drafts You can approve drafts at three levels of granularity: - \*\*Approve this section\*\* — Approves only the draft currently selected in the tree. - \*\*Approve all in this doc type\*\* — Approves every approvable draft within the current documentation type. - \*\*Approve all\*\* — Approves every approvable draft across all documentation types for this pull request. Once you approve a draft, its status badge updates to \*\*Approved\*\* and it becomes eligible for deployment. You can approve and deploy in a single action using the \*\*Approve and Deploy\*\* option. ### Deploying Drafts You can deploy drafts that have been approved, or use the combined \*\*Approve and Deploy\*\* action to approve and publish in one step. Deploy options follow the same three levels of granularity as approval — section, doc type, or all. If a draft has already been deployed, you can force a redeploy to push the current content again. ### Rejecting Drafts To reject a draft, select it in the tree and choose \*\*Reject\*\*. You will be prompted to enter a reason for rejection. The agent can use your reason to guide a regeneration. For proposed new sections, you can also reject the proposal outright to remove it from the tree. ### Regenerating Drafts If a draft does not meet your expectations, you can ask the agent to regenerate it. Select the draft and choose \*\*Regenerate\*\*. The agent rewrites the content based on the latest code changes and any directions you have configured.
