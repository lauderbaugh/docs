\## Managing Documentation Drafts When the documentation agent processes a pull request, it generates drafts organised by documentation type and section. You can review, edit, approve, reject, regenerate, and deploy each draft individually or in bulk. ### Understanding Draft Status Each draft displays a status badge so you can see its current state at a glance: - \*\*Pending\*\* — The draft is waiting for your review. - \*\*Approved\*\* — You have approved the draft and it is ready to deploy. - \*\*Rejected\*\* — You have rejected the draft. You can regenerate it if needed. - \*\*Not Applicable\*\* — The agent determined this section does not require documentation for this change. - \*\*Deployed\*\* — The draft has been published to your documentation. ### Navigating the Section Tree The review page displays a section tree on the left side of the screen. Each node in the tree represents a documentation section. Select a node to open that section's draft in the editor on the right. The tree groups sections by documentation type. Within each type, sections nest according to your documentation hierarchy. Use the doc type tabs at the top of the tree to switch between your enabled doc types — for example, \*\*User-Facing\*\*, \*\*Internal\*\*, and \*\*API\*\*. ### Reviewing and Editing a Draft To review a draft: 1. Select a section in the tree. 2. Read the generated content in the editor panel. 3. Make any edits directly in the editor. 4. Choose one of the actions described below. If a draft is marked \*\*Not Applicable\*\*, it means the agent determined no documentation update is needed for that section. You can still regenerate it if you disagree. ### Approving Drafts You can approve drafts at three levels of granularity: - \*\*Approve this section\*\* — Approves only the draft currently selected in the tree. - \*\*Approve all in this doc type\*\* — Approves every approvable draft within the current documentation type. - \*\*Approve all\*\* — Approves every approvable draft across all documentation types for this pull request. Once you approve a draft, its status badge updates to \*\*Approved\*\* and it becomes eligible for deployment. ### Proposed Sections Alongside updates to existing sections, the agent may propose entirely new sections that do not yet exist in your documentation structure. Proposed sections appear separately in the section tree. You can approve, reject, or change the parent of a proposed section before deploying it.
