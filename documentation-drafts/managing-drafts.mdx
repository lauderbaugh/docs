\## Managing Documentation Drafts When the documentation agent processes a pull request, it generates drafts organized by documentation type and section. You can review, edit, approve, reject, regenerate, and deploy each draft individually or in bulk. ### Understanding Draft Status Each draft displays a status badge so you can see its current state at a glance: - \*\*Pending\*\* — The draft is waiting for your review. - \*\*In Review\*\* — The draft is actively being reviewed. - \*\*Approved\*\* — You have approved the draft and it is ready to deploy. - \*\*Rejected\*\* — You have rejected the draft. You can regenerate it if needed. - \*\*Failed\*\* — The deployment attempt encountered an error. - \*\*Not Applicable\*\* — The agent determined this section does not require documentation for this change. - \*\*Deployed\*\* — The draft has been published to your documentation. ### Navigating the Section Tree The review page displays a section tree on the left side of the screen. Each node in the tree represents a documentation section. Select a node to open that section's draft in the editor on the right. The tree groups sections by documentation type. Within each type, sections nest according to your documentation hierarchy. Sections with a pending draft are highlighted so you can find them quickly. ### Proposed Sections In addition to updates to existing sections, the agent may propose entirely new sections it believes your documentation is missing. Proposed sections appear in the tree alongside regular drafts and are clearly labelled. You can: - \*\*Accept a proposal\*\* — approve and deploy it like any other draft. - \*\*Change the parent\*\* — reassign a proposed section to a different parent node before approving. - \*\*Reject a proposal\*\* — dismiss it if you do not want the new section created. ### Reviewing and Editing a Draft To review a draft: 1. Select a section in the tree. 2. Read the generated content in the editor panel. 3. Make any edits directly in the editor. 4. Choose one of the actions described below. If a draft is marked \*\*Not Applicable\*\*, it means the agent determined no documentation update is needed for that section. You can still regenerate it if you disagree. ### Approving Drafts You can approve drafts at three levels of granularity: - \*\*Approve this section\*\* — approves only the draft currently selected in the tree. - \*\*Approve all in this doc type\*\* — approves every approvable draft within the current documentation type. - \*\*Approve all\*\* — approves every approvable draft across all documentation types for this pull request. Once you approve a draft, its status badge updates to \*\*Approved\*\* and it becomes eligible for deployment. ### Deploying Drafts You can deploy approved drafts directly from the review interface. The deploy action is available at the same three levels of granularity as approval: - \*\*Deploy this section\*\* — deploys only the currently selected draft. - \*\*Deploy all in this doc type\*\* — deploys every approved draft within the current documentation type. - \*\*Deploy all\*\* — deploys every approved draft across all documentation types. You can also use \*\*Approve and Deploy\*\* to approve and publish a draft in a single action. ### Rejecting Drafts If a generated draft is not suitable, you can reject it. When you reject a draft, you are prompted to provide a reason. The reason is recorded and can inform future agent revisions. ### Regenerating Drafts If you reject a draft or want the agent to produce a fresh version, select \*\*Regenerate\*\*. The agent rewrites the draft for the selected section and replaces the previous content. ### The Debug Panel The review interface includes a debug panel you can toggle to inspect raw draft metadata, including the resolved agent directions and staleness check results that influenced the generated content.
