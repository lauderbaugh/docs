\## Deploy Modes The review interface supports three deployment modes. Each mode determines which actions are available in the action bar and what the confirmation modal shows before you proceed. ### Approve In \*\*Approve\*\* mode, the action bar lets you approve drafts without immediately publishing them. Use this when you want to sign off on content but intend to deploy later — for example at the end of a review cycle. Approve actions are available at three scopes: - \*\*This section\*\* — approves only the currently selected draft. - \*\*All in this doc type\*\* — approves every approvable draft within the active documentation type. - \*\*All\*\* — approves every approvable draft across all documentation types for this pull request. ### Deploy In \*\*Deploy\*\* mode, the action bar lets you publish drafts that are already in the \*\*Approved\*\* state. Drafts that have not yet been approved are skipped. Deploy actions follow the same three-scope model as approve actions. ### Approve and Deploy \*\*Approve and Deploy\*\* combines both steps. The system approves each eligible draft and immediately queues it for deployment. Use this when you are confident in the generated content and want to publish without a separate deploy step. ### Confirmation Modal For actions that affect more than one section, a confirmation modal appears before anything is processed. The modal lists every draft that will be affected, grouped into: - \*\*Updates\*\* — drafts targeting sections that already exist in your documentation. - \*\*Proposals\*\* — drafts that will create new sections. Review the list carefully, then confirm to proceed. If you are in \*\*Approve and Deploy\*\* mode, the modal title and button text reflect the combined action so it is clear that both steps will run.
