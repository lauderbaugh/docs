\## Bootstrapping Documentation Bootstrapping lets the documentation agent generate an initial documentation structure from a code change when no existing sections are present. Instead of only updating known sections, the agent proposes both the content and the location in your documentation hierarchy. ### When Bootstrapping Runs Bootstrapping runs when the agent processes a code change but finds no existing documentation nodes to update. This typically happens: - During the initial onboarding of a repository before you have confirmed a skeleton. - When a new doc type is enabled for the first time on an existing repository. ### What Bootstrapping Produces The agent analyses the code change and your target documentation type, then produces: - Proposed page content for each new section it identifies. - A suggested location in the documentation hierarchy (parent page and section path) for each new page. - A nesting level indicating whether the page should be top-level, a sub-page, or a section within an existing page. You review and act on these proposals the same way you handle any other proposed draft — you can accept, reassign to a different parent, or reject each one individually. ### Bootstrapping vs. Gap Analysis Gap analysis runs on every code change and proposes new sections only when existing content is missing coverage. Bootstrapping is a one-time process that generates the initial structure when no sections exist at all. After bootstrapping, the agent switches to gap analysis for subsequent changes.
