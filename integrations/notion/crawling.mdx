\## Crawling Your Notion Workspace Syscribe can read your existing Notion workspace to build or refresh your documentation skeleton. The crawler traverses your page hierarchy, reads page titles and content, and maps the structure into Syscribe's section tree. ### How the Crawler Works When you trigger a crawl, Syscribe: 1. Starts from the root page ID you configured in your deployment target settings. 2. Fetches the blocks on that page and identifies child pages. 3. Recursively visits each child page, building a tree of nodes and edges. 4. Extracts the title and plain-text content of each page to populate the section metadata. 5. Applies a short delay between requests to respect Notion's API rate limits. The crawler stops traversal at \*\*10 levels deep\*\* to prevent runaway scans on very large workspaces. Pages beyond that depth are not included in the proposed skeleton. ### What the Crawler Produces The crawl result contains: - \*\*Nodes\*\* — each discovered page becomes a node with a section path, title, content, and an optional doc type inferred from the page content. - \*\*Edges\*\* — the parent–child relationships between pages are recorded as edges, so Syscribe can reconstruct the hierarchy. Syscribe uses this structure to propose a documentation skeleton. You review and confirm the skeleton before any pages are written or modified. ### Triggering a Crawl 1. Navigate to your repository settings and open the deployment target configuration for your Notion-connected doc type. 2. Select \*\*Rescan\*\* or \*\*Rediscover\*\* to start the crawler. 3. Wait for the crawl to complete — the status indicator in the settings panel updates in real time. 4. Review the proposed skeleton and confirm it. ### Rate Limiting The crawler inserts a delay between each API request to avoid hitting Notion's rate limits. If you have a very large workspace with many nested pages, the initial crawl may take several minutes. You can monitor progress in the repository settings panel. ### Supported Block Types The crawler reads the following Notion block types when extracting page content: - Paragraph blocks - Heading 1, 2, and 3 blocks - Child page blocks (used to discover sub-pages) Other block types — such as databases, images, and embeds — are skipped during content extraction but do not stop the crawler from continuing.
