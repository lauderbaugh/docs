---
title: "Managing Mintlify Navigation"
---

\## Managing Mintlify Navigation Every time you deploy a draft to Mintlify, the integration updates your \`docs.json\` file to ensure the new page appears in your site's navigation. You do not need to edit \`docs.json\` manually. ### Navigation Groups Pages are organised into navigation groups based on their doc type: - \*\*User-Facing\*\* docs are placed in the \_Guides\_ group. - \*\*Internal\*\* docs are placed in the \_Internal\_ group. - \*\*API\*\* docs are placed in the \_API Reference\_ group. If a matching group does not exist in your \`docs.json\`, the integration creates it automatically. If the same page path already exists in the navigation, the integration skips adding it again — so redeploying the same draft never creates duplicate entries. ### Deduplication After adding new pages to the navigation, the integration scans all navigation groups and removes any duplicate page paths within the same group. This keeps your \`docs.json\` clean even if you deploy the same section multiple times or run a bulk push. ### File Path Resolution The integration derives the file path for each MDX file from the doc type and section path. For example, a user-facing page with the section path \`authentication/overview\` is written to \`guides/authentication/overview.mdx\` inside your configured base path. ### Bulk Navigation Updates When you deploy multiple drafts at once, the integration batches the navigation updates into a single \`docs.json\` write. This avoids conflicts that would occur if each draft tried to update the file independently. ### docs.json Format Compatibility The integration supports both the current object-based \`docs.json\` format used by Mintlify v4 and the older array-based navigation format used by earlier versions. You do not need to migrate your configuration — the integration detects the format automatically.
