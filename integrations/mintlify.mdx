\## Mintlify Integration The Mintlify integration publishes your approved documentation drafts as MDX files to a GitHub repository that serves your Mintlify docs site. It also keeps your \`docs.json\` navigation file up to date so new pages appear in your site automatically. ### How It Works When you deploy a draft, the integration: 1. Converts the draft content to MDX format, including any required frontmatter. 2. Writes the MDX file to the correct path in your configured repository and branch. 3. Updates the \`docs.json\` navigation to include the new page in the appropriate group. When you deploy multiple drafts at once, the integration batches the navigation updates into a single write to avoid conflicts. ### Configuration Fields To connect the Mintlify integration, provide the following fields in your doc type settings: - \*\*Repository\*\* — the GitHub repository that hosts your Mintlify site, in \`owner/repo\` format. - \*\*Branch\*\* — the branch to which the integration pushes changes. - \*\*Base path\*\* — the root folder inside the repository where your MDX files live. ### Fetching Existing Content The integration can read the current content of any section from your repository. Use \*\*Rescan\*\* in your repository settings to re-index existing pages without pushing new content — useful after you edit files directly in GitHub. ### Force Redeploying Content If a draft is already marked as \*\*Deployed\*\*, you can push it again without re-approving it. Select the deployed draft in the section tree and choose \*\*Redeploy\*\* to overwrite the existing file with the current draft content. ### Navigation Management See \[Managing Mintlify Navigation\](/integrations/mintlify/navigation) for full details on how the integration organises pages into navigation groups, resolves file paths, and handles \`docs.json\` format compatibility.
