\## Mintlify Integration The Mintlify integration publishes your approved documentation drafts as MDX files to a GitHub repository that serves a Mintlify docs site. It also keeps your \`docs.json\` navigation file up to date automatically. ### How It Works When you deploy an approved draft, the integration: 1. Converts your draft content to MDX format, including a frontmatter block with the page title and description. 2. Pushes the MDX file to the configured branch of your docs repository at the resolved file path. 3. Updates \`docs.json\` to add the new page to the correct navigation group — or skips the update if the page already exists in the navigation. 4. Deduplicates navigation entries to ensure no page path appears twice in the same group. ### Configuration To connect a doc type to a Mintlify site, provide the following fields in your deployment target settings: - \*\*Repository\*\* — the GitHub repository in \`owner/repo\` format that hosts your Mintlify site. - \*\*Branch\*\* — the branch to push files and navigation updates to (for example, \`main\`). - \*\*Base path\*\* — the folder inside the repository where MDX files are written. ### Fetching Existing Content Before the integration pushes a new draft, it fetches the current content of the target MDX file (if it exists) and computes a content hash. You can use this hash to detect whether the remote file has changed since your last deployment. ### Bulk Push You can deploy multiple drafts to Mintlify in a single operation. The integration processes each draft in sequence and batches all navigation updates into one \`docs.json\` write at the end, avoiding write conflicts. ### Navigation Management See \[Managing Mintlify Navigation\](/integrations/mintlify/navigation) for details on how pages are placed into navigation groups, how duplicates are handled, and how \`docs.json\` format compatibility works.
