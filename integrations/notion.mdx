# Connecting Notion

Syscribe integrates with Notion via Notion's official API. When a draft is approved, Syscribe makes surgical updates to specific sections of your Notion pages — replacing only the content it owns, leaving everything else untouched.

This guide walks you through creating a Notion integration, sharing the right pages with it, and configuring the target in Syscribe.

---

## Before you start

You will need:

- A Notion workspace where you have admin or full-access permissions
- A Syscribe account with at least one repo connected

---

## How Syscribe writes to Notion

Syscribe uses the Notion API to update your pages directly. Key behaviours:

- **Surgical section updates only.** Syscribe does not rewrite entire pages. It finds the specific `##` heading (H2 block) that corresponds to a section it owns, and replaces the content beneath that heading — stopping at the next H2 or the end of the page. Everything above, below, and between Syscribe's sections is untouched.
- **Sub-pages and databases within a section are never deleted.** If you have embedded databases or child pages inside a section Syscribe manages, they are preserved on every update.
- **Syscribe writes native Notion blocks**, not raw text — headings, paragraphs, bulleted lists, code blocks, and callouts are all rendered as proper Notion block types.
- **Syscribe only accesses pages you explicitly share with it.** Notion's permission model requires you to grant the integration access to specific pages. It cannot discover or access pages that have not been shared.

---

## Step 1 — Create a Notion integration

1. Go to [notion.so/profile/integrations](https://www.notion.so/profile/integrations) and click **New integration**
2. Give it a name: `Syscribe`
3. Select the workspace you want Syscribe to write to
4. Under **Capabilities**, ensure the following are enabled:
   - **Read content** ✓
   - **Update content** ✓
   - **Insert content** ✓
   - **Read comments** — optional, not required
   - **Create comments** — optional, not required
5. Under **User capabilities**, leave at **No user information** (Syscribe does not need user identity)
6. Click **Save**
7. Copy the **Internal Integration Token** shown on the integration page — this starts with `secret_`. You will need this in Step 3.

---

## Step 2 — Share your pages with the integration

Notion integrations can only access pages that have been explicitly shared with them. This is a Notion security requirement — Syscribe cannot bypass it.

**For each page you want Syscribe to manage:**

1. Open the page in Notion
2. Click **...** (three dots) in the top right → **Connections**
3. Search for `Syscribe` (the integration you just created) and click **Confirm**

You only need to share the **top-level parent page** in a hierarchy — Notion propagates integration access to all child pages automatically. If you are using Syscribe for internal developer documentation, sharing your top-level "Engineering" or "Internal docs" page is sufficient to give Syscribe access to all pages beneath it.

**Important:** If you create new top-level pages in the future that you want Syscribe to manage, you will need to share them with the integration manually. Syscribe cannot discover pages that have not been shared, even if they are in the same workspace.

---

## Step 3 — Find your page ID

Syscribe needs the ID of the Notion page where it will write. This is the root page under which your documentation lives.

To find a page ID:

1. Open the page in Notion
2. Click **Share** → **Copy link**
3. The URL looks like: `https://notion.so/your-workspace/Page-Title-abc123def456...`
4. The page ID is the last part of the URL — the 32-character string after the final `-` or `/`
   - Example URL: `https://notion.so/acme/Engineering-Docs-4a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d`
   - Page ID: `4a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d`

You can also find the page ID via the Notion API if you prefer — make a `GET /v1/search` call with your integration token and look for your page in the results.

---

## Step 4 — Connect the target in Syscribe

1. In Syscribe, go to **Repos** and select the repo you want to connect
2. Under **Doc types**, find the doc type you want to route to Notion (typically `INTERNAL`)
3. Click **Configure target** and select **Notion**
4. Fill in the following fields:

| Field | Value |
|---|---|
| **Page ID** | The 32-character ID from Step 3 |
| **Integration token** | The `secret_...` token from Step 1 |

5. Click **Save**

Syscribe will immediately attempt to read the page you specified to verify the connection. If verification fails, the most common causes are: the page has not been shared with the integration (Step 2), the page ID is incorrect, or the integration token is wrong.

---

## Step 5 — Onboarding crawl

When you save the target configuration for the first time, Syscribe crawls your Notion page hierarchy to build its initial understanding of your documentation structure.

**What the crawl does:**

- Traverses all child pages beneath the configured root page, up to 10 levels deep
- Reads the content of each page and infers what it covers
- Maps each page to a doc type (INTERNAL, USER_FACING, API, etc.)
- Identifies the H2 heading structure within each page — these become the sections Syscribe can surgically update
- Builds the knowledge graph: a structured map of every section, what code it relates to, and how fresh it is

**What you see:**

The Syscribe UI shows crawl progress. When complete, you are taken to the **Documentation landscape** review screen. Review the discovered pages, correct any miscategorisations, and click **Confirm**. This becomes Syscribe's confirmed baseline — it will not restructure or reorder confirmed sections without your explicit action.

**Crawl rate:** Syscribe fetches Notion pages at a rate of one per 100ms to stay within Notion's API limits (3 requests/second). A workspace with 100 pages takes approximately 10–15 seconds to crawl.

**If your Notion workspace has no content yet:**

Syscribe detects this and proposes a documentation skeleton — an ordered set of pages and sections appropriate for your doc type. You review and adjust the skeleton, confirm it, and Syscribe creates stub pages in Notion. From that point, each PR fills in the skeleton surgically.

## Constraints and known limitations

### Only pages shared with the integration are accessible

As described in Step 2, Notion's permission model requires explicit sharing. If Syscribe reports that it cannot find a page during the crawl, the most likely cause is that the page (or one of its ancestors) has not been shared with the integration.

To verify: open the page in Notion, click **...** → **Connections**, and confirm the Syscribe integration is listed.

### Section boundaries are H2 headings

Syscribe's unit of ownership within a Notion page is one H2 block — the heading and all content beneath it until the next H2 heading or end of page. This means:

- Each section Syscribe manages maps to exactly one H2 heading
- H1 headings are treated as page titles and are never modified by Syscribe
- H3 and deeper headings are part of the H2 section and are updated as a unit with their parent H2
- Content above the first H2 on a page (introductory text, callout banners, etc.) is never touched by Syscribe

**Implication for your pages:** If you want Syscribe to manage a specific topic, it should have its own H2 heading. A page with no H2 headings is treated as a single undivided section — Syscribe will manage the entire page body as one unit when updating it.

### Standalone pages vs. database pages

Notion has two types of pages: **standalone pages** (whose parent is another page) and **database pages** (rows in a Notion database). Syscribe works with both, but they behave differently:

- **Standalone pages** are the primary target. Syscribe creates and updates these via the standard page API.
- **Database pages** are supported for reading during the crawl, but Syscribe's skeleton scaffolding creates standalone pages. If your documentation lives inside a Notion database, contact us — this configuration requires additional setup.

### Large workspaces

Notion's API returns up to 100 child blocks per request. For pages with many blocks (more than ~50 paragraphs), the crawl makes multiple paginated API calls. The crawl handles this automatically, but very large pages (over 5,000 characters of content) are flagged in the landscape review UI for your attention.

The crawl traverses up to **10 levels of nesting**. Pages nested deeper than 10 levels are not discovered. In practice, documentation hierarchies rarely exceed 4–5 levels.

### Eventual consistency on new pages

Newly created Notion pages may not appear in Notion's search index immediately. Syscribe's crawl uses direct block traversal (not the search API) so this does not affect the crawl itself — but if you create a new page and it does not appear in the Syscribe landscape summary, triggering a re-scan from the repo settings page will pick it up.

### Token security

Your Notion integration token (`secret_...`) is stored encrypted in Syscribe. It is scoped to the specific workspace you selected when creating the integration — it cannot access other workspaces. If you need to revoke Syscribe's access at any time, go to [notion.so/profile/integrations](https://www.notion.so/profile/integrations), find the Syscribe integration, and click **Delete integration**.
